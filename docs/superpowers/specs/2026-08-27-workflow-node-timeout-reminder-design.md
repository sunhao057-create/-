# 项目管理系统 — 流程节点超时提醒设计

日期：2026-08-27  
状态：待实现（方案 1 已确认）

## 目标

流程引擎里每个**会停下来等人办理**的节点，都可以自己设定超时时长。到期仍未办理时，在「我的待办」和单据流程条上标成「已超时」。不另发消息，不自动通过。

## 非目标

- 不发邮件、短信、站内新消息
- 不自动同意、跳过或转交
- 不按固定间隔重复催办
- 开始、结束、抄送、分支、条件节点不设超时（它们不会停在待办上，或会自动往下走）
- 不改已经发出的待办的截止时间（以后改流程图只影响新进入该节点的待办）

界面文案只用中文。不使用 Coze。

## 已确认选择

| 项 | 选择 |
|---|---|
| 提醒形态 | 待办红色「已超时」标签 + 可筛选；不另插消息 |
| 时长 | 数字 + 单位（小时或天）；不填或 0 表示不超时 |
| 展示位置 | 我的待办列表 + 打开单据时的流程条 |

## 节点设置

仅 `APPROVAL` / `TASK`（保存时 `TASK` 仍归一成审批节点）显示「超时」：

- 数字：正整数，1–999
- 单位：小时 / 天，默认小时
- 不填或 0：关闭超时
- 填了数字必须选单位；单位为小时或天以外则保存失败，中文提示「超时时限单位只能是小时或天」
- 帮助文案：「超过此时限仍未办理，待办和单据上将标记已超时。」

图节点字段（随 `graph_json` 保存）：

| 字段 | 说明 |
|---|---|
| `timeoutValue` | 整数，可空；空或 0 表示关闭 |
| `timeoutUnit` | `HOUR` 或 `DAY`；关闭时可空 |

旧流程图没有这两项时视为不超时。

## 运行时

待办 `wf_task` 增加可空 `due_at`。创建审批待办时：

- 节点未开超时：`due_at` 为空
- 小时：`due_at = created_at + timeoutValue 小时`
- 天：`due_at = created_at + timeoutValue 天`（按自然日，例如 1 天 = 创建时刻加 24×1 小时的日历加天，用 `plusDays`）

抄送任务不写 `due_at`。

**已超时：** 任务状态为 `PENDING`，且 `due_at` 非空，且当前时间晚于 `due_at`。已办、已取消不算超时。

生产库用现有 `SchemaRepairer` 给 `wf_task` 补 `due_at datetime NULL`。

## 待办列表

`InboxItemView` 增加：

- `dueAt`：截止时间，可空
- `overdue`：是否已超时

「待办处理」「退回处理」页：

- 状态列旁或状态列内：超时则红色标签「已超时」
- 增加「仅看超时」开关；打开后只显示 `overdue == true` 的行
- 查询：`GET /api/inbox?type=TODO|RETURNED&overdue=true`（`overdue` 缺省为 false，不加筛选）

已办、抄送、草稿不展示超时标签和筛选。

## 单据流程条

`WorkflowRuntimeView` 增加 `dueAt`、`overdue`：取当前节点上**任意一条仍待处理的审批任务**的截止时间（同一节点多人办理时，任一待办超时即整节点标超时；展示的 `dueAt` 用这些待办里最早的截止时间）。

流程条在「当前：节点名」旁：已超时则红色「已超时」；有 `dueAt` 且未超时可不额外展示倒计时（本期不做剩余时间）。

## 错误处理

- 超时时限不是正整数或大于 999：保存流程失败，「超时时限必须是 1 到 999 的整数」
- 开了超时但单位非法：见上
- 未开超时的节点照常保存

## 测试要点

- 保存带 8 小时超时的审批节点，发布后提交单据，该待办 `dueAt` 约等于创建时间 + 8 小时，当时 `overdue` 为 false
- 把该待办 `due_at` 改到过去，列表带 `overdue=true` 能查到，标签为已超时；流程条 `overdue` 为 true
- 办完后不再超时
- 抄送节点保存时忽略超时字段
- 未设超时的旧流程待办 `dueAt` 为空，不过滤进「仅看超时」

## 范围外以后可做

重复催办、邮件、超时自动转交或通过。
