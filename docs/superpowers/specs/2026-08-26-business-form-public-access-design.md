# 项目管理系统 — 业务表单公开访问设计

日期：2026-08-26  
状态：待实现（设计已口头确认）

本说明覆盖两件事：1）以后新增的业务表单默认能在角色里控制公开访问；2）付款申请补齐与项目 / 客户 / 供应商相同的公开办理。

付款申请原设计「不开放公开办理」「`canBePublic = false`」以本文为准。

## 目标

- 有数据范围且能新增的业务表单，在「公开访客」角色里都能勾公开、展示、填报、查询、导出。
- 付款申请走完整公开办理：公开页可展示 / 填报 / 查询 / 导出；后台单据可勾「允许公开」。
- 内部角色的查看 / 新增 / 编辑 / 删除 / 导入导出不变。公开访客默认全关，由管理员在角色管理打开后才出现在公开办理页。

界面文案只用中文。

## 非目标

- 不把预算、账号、角色、流程、系统名称 / 图标、主题开放给公开页
- 不做通用字段引擎一次性生成所有公开表单
- 本期不为客户 / 供应商 / 项目重写公开页
- 公开付款详情不展示预算扣减、可用金额、已付合计、流程内部状态
- 不在公开填报时拦截超预算

## 哪些模块可以公开

`FormModule.canBePublic()` 改为：

```
hasDataScope() && hasCreate()
```

当前为真：项目管理、付款申请、客户管理、供应商管理。  
当前为假：预算管理、账号管理、角色管理、流程引擎、系统名称 / 图标、主题风格。

以后新增业务表单只要同样标成「有数据范围 + 能新增」，公开访客权限树会自动出现该模块。公开列表和填报页仍要按该表单单独做（与项目相同，不是自动生成）。

前端 `hasPublicAccess` 不再写死三个模块，跟后端 `canBePublic` 走。

## 角色

编辑「公开访客」时，权限树显示所有 `canBePublic` 的模块（现为四个）。每块：

1. 公开（总开关）
2. 仅当公开勾选后出现：展示、填报、查询、导出
3. 取消公开时，子项一律关闭并保存为否

其它角色的权限树不出现这组公开开关。运行时公开页只读 `PUBLIC_GUEST`。

种子：公开访客对付款申请默认全关。管理员已有的公开访客勾选不受影响。

## 记录级「允许公开」

`pm_payment` 增加：

| 字段 | 说明 |
|---|---|
| `is_public` | 布尔，默认否 |
| `submit_source` | `ADMIN` 或 `PUBLIC`，默认 `ADMIN` |

启动时用现有 SchemaRepairer 补列。后台付款列表和单据页增加「允许公开」，默认不勾。

公开页展示和查询只返回 `is_public = true` 的付款单。未公开记录按不存在处理（列表不含，详情 404「内容不存在」）。

公开页提交的新单：`is_public = false`，`submit_source = PUBLIC`，启动已发布的付款申请流程。流程到达结束节点后仍按现有规则扣该项目可用金额。后台勾选「允许公开」后才进入公开列表和查询。

## 公开页

- 首页 `/public` 按配置里 `publicAccess = true` 的模块出卡片，不再写死项目 / 客户 / 供应商三个
- 侧栏同样按配置增加「付款申请」
- 直接访问未开放路径：页内「该内容未开放公开办理」

| 路径 | 条件 | 内容 |
|---|---|---|
| `/public/payments` | 付款公开且展示 | 列表 |
| `/public/payments/new` | 付款公开且填报 | 填报 |
| `/public/payments/query` | 付款公开且查询 | 按申请编码或事由查询 |
| `/public/payments/:id` | 付款公开且（展示或查询） | 只读详情 |

仅勾查询、未勾展示：空关键词返回空列表，有关键词才返回已公开单据。

展示且填报时列表工具栏有「新建」。有导出权限时列表可导出 CSV。无编辑、删除、导入。

### 公开列表 / 详情字段

编码、关联项目（名称 + 编码）、供应商、金额、事由、付款方式、期望付款日、附件、收款账户（户名、开户行、账号、网点，与公开供应商详情一致）。

### 公开填报字段

关联项目、金额、付款事由、供应商、收款账户、付款方式、期望付款日、附件。必填规则与后台新建一致。

关联项目、供应商只能选自已勾「允许公开」的记录。收款账户来自所选公开供应商。选未公开项目或供应商时接口拒绝。

填报成功提示：「已提交，待后台审核后公开」。

## 接口

`GET /api/public/config` 在保留 `project` / `customer` / `supplier` 的同时增加：

- `payment`：付款申请开关，结构与另外三个相同
- `modules`：数组，每项 `{ module, moduleLabel, path, flags }`，供首页和侧栏遍历。`path` 为 `/public/projects`、`/public/payments`、`/public/customers`、`/public/suppliers`

新增：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/public/payments` | `keyword` 可选；需展示或查询 |
| GET | `/api/public/payments/{id}` | 需展示或查询；未公开 404 |
| POST | `/api/public/payments` | multipart 填报；需填报；限流与项目填报相同 |
| GET | `/api/public/payments/lookups` | 需填报；返回已公开项目、已公开供应商及其银行账户 |

未开放时：列表 / 详情 / lookups 返回「该内容未开放公开办理」；填报返回「该表单未开放填报」。

后台付款读写接口带上 `isPublic`、`submitSource`，权限仍走 `PAYMENT` 的查看 / 编辑。

## 以后新增业务表单

清单（付款申请本期一次做完，作对照）：

1. `FormModule` 标 `hasDataScope`、`hasCreate`（即可公开）
2. 实体加 `is_public`、`submit_source`，SchemaRepairer 补列
3. 公开配置 `modules` 增加一项及对应 `path`
4. 公开 list / get / submit / lookups 与公开页（列表、填报、查询、详情）
5. 后台列表和表单加「允许公开」
6. 测试：角色 `hasPublicAccess`、config 开关、填报来源、未公开不可见、未公开关联拒绝

## 测试

`PublicPortalApiTests`（及必要的角色 / 付款测试）覆盖：

- 公开访客：付款申请 `hasPublicAccess = true`；预算、账号、角色、流程、主题为 `false`
- 勾选公开访客付款申请后，config 中 `payment` 与 `modules` 内该项一致
- 未勾公开时，付款公开接口全部拒绝
- 项目与供应商均已公开时，公开填报付款成功：`submitSource = PUBLIC`、默认不公开、已启动流程、未扣预算
- 选未公开项目或未公开供应商时填报失败
- 仅展示：公开列表只含后台已勾「允许公开」的单据
- 仅查询：空关键词空列表，有关键词才出已公开单据
- 限流与项目填报相同

浏览器：角色打开付款申请公开权限 → 公开首页出现卡片 → 填报 → 后台可见并可勾「允许公开」→ 公开列表能看见。
