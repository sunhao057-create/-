# 项目管理系统 — 公开办理页设计

日期：2026-08-26  
状态：待实现（设计已口头确认）

## 目标

提供不登录即可访问的公开办理页，视觉与表单控件与管理后台一致。访客能看到什么、能否填报、能否查询，只由内置角色「公开访客」在角色管理里的开关决定。所有未登录访客看到同一套结果。

## 非目标

- 不为访客单独做账号或验证码登录
- 不把预算、账号、角色、流程、系统名称开放给公开页
- 公开填报不启动流程引擎
- 不在本期做附件上传、预算填写、银行账号公开填报

## 角色：公开访客

- 名称：公开访客
- 编码：`PUBLIC_GUEST`
- `builtin = true`
- 启动时若不存在则创建；权限默认全关（三个模块均未公开）
- 不能删除
- 不能分配给任何用户（账号管理的角色下拉不出现此项；接口拒绝把用户角色设为 `PUBLIC_GUEST`）
- 其它角色的权限树不出现「公开 / 展示 / 填报 / 查询」

编辑「公开访客」时，权限树只显示：

- 项目管理
- 客户管理
- 供应商管理

每块：

1. 公开（总开关）
2. 仅当公开勾选后出现：展示、填报、查询
3. 取消公开时，展示、填报、查询一律关闭并保存为否

管理员改的是这份角色权限；公开页运行时只读 `PUBLIC_GUEST`，不取其它角色的并集。

## 记录级「允许公开」

`pm_project`、`crm_customer`、`crm_supplier` 增加：

- `is_public`：布尔，默认否
- `submit_source`：`ADMIN` 或 `PUBLIC`，默认 `ADMIN`

后台新建/编辑表单增加勾选「允许公开」，默认不勾。后台列表可按已公开 / 未公开筛选。

公开页展示和查询 **只返回 `is_public = true` 的记录**。未公开记录按不存在处理（查询接口返回空列表，详情返回 404），不暗示库里有这条数据。

公开页提交的新记录：`is_public = false`，`submit_source = PUBLIC`。后台勾选「允许公开」后才进入展示和查询。

## 公开页

- 地址：`/public`，不走登录 Guard
- 登录页增加「公开办理」
- 顶栏右侧无头像、无退出，仅「登录后台」
- 使用现有品牌（名称、图标）和主题变量，卡片/表格/按钮/表单与后台同一套样式
- 左侧菜单只出现已勾选「公开」的模块；子入口随展示 / 填报 / 查询开关出现

路由：

| 路径 | 条件 | 内容 |
|---|---|---|
| `/public` | 至少一个模块公开 | 说明文案 + 进入已开放模块 |
| `/public` | 全部未公开 | 「暂未开放公开办理」+ 登录后台 |
| `/public/projects` | 项目公开且展示 | 列表 |
| `/public/projects/new` | 项目公开且填报 | 填报表单 |
| `/public/projects/:id` | 项目公开且（展示或查询） | 只读详情；未公开 id 当 404 |
| `/public/projects/query` | 项目公开且查询 | 按编码或名称查询 |
| 客户 / 供应商 | 同上 | `/public/customers`、`/public/suppliers` 及 `new` / `:id` / `query` |

直接访问未开放路径：页内中文提示「该内容未开放公开办理」，不跳登录。

列表：搜索框 + 表格 + 「暂无数据」，无编辑、删除、导入导出。展示且填报时工具栏有「新建」。

## 对外字段

### 项目

展示 / 查询只读：名称、编码、公司名称、状态、概况。不返回预算、附件、负责人、区域、客户内部 id 以外的关联账号。

填报字段：名称、公司名称、概况、联系人、联系电话。

提交处理：

- 编码由系统生成，格式 `PUB` + 年月日 + 四位序号，保证唯一
- 按公司名称精确匹配已有客户；没有则新建一条未公开客户（简称取公司名前 50 字，等级「一般重要」，一条联系人），项目挂到该客户
- 负责人取系统管理员账号；区域取 id 最小的一条区域。若没有区域或没有管理员，返回「暂无法提交，请联系管理员」
- 不出现员工、区域下拉
- 不触发流程引擎

### 客户

展示 / 查询：简称、公司名、编码、等级。不返回银行账号。

填报：简称、公司名、联系人姓名、联系电话。编码系统生成。不填银行账号。

### 供应商

与客户对等。类型字段公开填报固定为后台默认值「原材料」，页面不出现类型下拉。

## 接口

均不要求登录。其它 `/api/**` 仍需登录。`GET /api/branding`、`/uploads/**` 维持现有公开。

- `GET /api/public/config`  
  返回三模块的 `public`、`display`、`submit`、`query`。未创建公开访客角色时视为全关。

- `GET /api/public/projects?keyword=`  
  仅 `is_public=true`。模块未开展示且未开查询时返回业务错误「该内容未开放公开办理」。仅开查询、未开展示时：无 keyword 返回空列表；有 keyword 才按编码或名称匹配公开记录。

- `GET /api/public/projects/{id}`  
  仅公开记录；否则 404。需展示或查询已开。

- `POST /api/public/projects`  
  需填报已开。校验失败用字段错误。成功中文「已提交，待后台审核后公开」。

客户、供应商同样三套路径：`/api/public/customers`、`/api/public/suppliers`。

后台原有保存接口增加读写 `isPublic`。角色读写增加 `publicAccess`、`publicDisplay`、`publicSubmit`、`publicQuery`（仅对公开访客有意义；其它角色保存时强制为否）。

## 错误与限流

- 功能未开：400，中文「该内容未开放公开办理」或「该表单未开放填报」
- 记录未公开或不存在：404
- 校验失败：400，字段级中文
- 同一 IP、同一模块，10 分钟内填报超过 10 次：429，「提交过于频繁，请稍后再试」
- 公开接口不返回负责人账号、预算、银行账号

## 安全边界

- 公开访客权限与员工权限分离，员工角色不能靠勾选把全站公开
- 填报默认不公开
- 查询不得用于探测未公开编码是否存在（未公开与不存在均为空列表或 404）

## 测试

- 公开访客未勾公开：config 全关；列表/提交失败
- 只开展示：能列表（仅已公开记录），不能提交
- 只开查询：无关键字为空；关键字能命中已公开，不能命中未公开
- 只开填报：能提交，记录 `is_public=false`、`submit_source=PUBLIC`
- 不能删除公开访客，不能把该角色赋给用户
- 编辑其它角色时请求里即使带上公开字段也保存为否

## 主要落点

- 后端：`com.projectmgmt.portal`（公开接口与限流）、角色权限列、`SchemaRepairer` 补列、`RoleService` 种子
- 前端：`src/layouts/PublicLayout.tsx`、`src/pages/public/`、`src/api` 公开客户端；`App.tsx` 在 Guard 外挂路由；登录页入口；角色权限树在编辑公开访客时切换公开三项；项目/客户/供应商表单增加「允许公开」
